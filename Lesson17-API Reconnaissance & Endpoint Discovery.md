
# Module 17 — API Reconnaissance & Endpoint Discovery

> **Goal:** Learn how to systematically discover APIs, endpoints, parameters, versions, and hidden functionality using passive and active reconnaissance during an authorized security assessment.

---

# Chapter 1 — The API Attack Surface

Most people imagine an API like this:

```text
/api/login

/api/users

/api/orders
```

Reality looks more like:

```text
                    API
                     │
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
 REST API        GraphQL         WebSocket
      │              │              │
      ▼              ▼              ▼
 Mobile API     Admin API     Internal API
      │              │              │
      ▼              ▼              ▼
 Versioned      Debug API      Legacy API
```

Most APIs are much larger than they first appear.

---

# Chapter 2 — Recon First

Before testing anything, answer these questions:

- What domains exist?
    
- What subdomains exist?
    
- What API versions exist?
    
- What authentication methods exist?
    
- What technologies are used?
    
- What documentation exists?
    
- What endpoints exist?
    
- Which endpoints are public?
    
- Which require authentication?
    

This becomes your **attack surface map**.

# Chapter 4 — Starting with the Website

Open the application.

Don't click randomly.

Observe.

Open Developer Tools.

Look at the Network tab.

Example:

```text
GET /api/profile

GET /api/settings

POST /api/login

GET /api/products

POST /api/cart
```

Every request is a clue.

---

# Chapter 5 — Browser Developer Tools

The Network tab tells you:

- URLs
    
- Methods
    
- Headers
    
- Parameters
    
- JSON bodies
    
- Status codes
    
- Cookies
    
- Tokens
    

Example:

```http
POST /api/login

Content-Type: application/json
```

Body:

```json
{
  "email":"user@example.com",
  "password":"password"
}
```

You now know:

- Endpoint
    
- Method
    
- Request format
    

---

# Chapter 6 — Proxy Everything

A web proxy (such as Burp Suite or OWASP ZAP) lets you observe and inspect all HTTP(S) traffic generated by the application during an authorized assessment.

Example flow:

```text
Browser

↓

Proxy

↓

Target
```

Now every request is captured.

Nothing is missed.

Look for:

```text

/graphql

/admin

/internal

/auth

/upload
```

Also search for:


# Chapter 8 — Version Discovery

Many APIs have multiple versions.

Example:

```text
/api/v1/

/api/v2/

/api/v3/
```

Sometimes:

```text
/v1/

/v2/

/beta/

/legacy/
```

Older versions often receive less maintenance and deserve careful review.

---

# Chapter 9 — Documentation

Check for:

```text
/swagger

/swagger-ui

/api-docs

/openapi.json

/openapi.yaml
```

Documentation often contains:

- Every endpoint
    
- Parameters
    
- Response schemas
    
- Authentication methods
    
- Administrative endpoints
    

This can dramatically accelerate attack surface mapping.

---

# Chapter 10 — GraphQL Discovery

GraphQL often appears at:

```text
/graphql
```

or

```text
/api/graphql
```

Indicators include:

```http
POST /graphql
```

Payload:

```json
{
   "query":"..."
}
```

Once identified, GraphQL requires a different testing methodology than REST.

---

# Chapter 11 — WebSockets

Look for:

```text
ws://

wss://
```

Common uses:

- Chat
    
- Notifications
    
- Live updates
    
- Trading platforms
    
- Games
    

These APIs deserve their own security review.

# Chapter 12 — Mobile APIs

Mobile applications frequently use APIs that differ from the web application.

Possible discoveries:

```text
/api/mobile/

/v3/

/internal/mobile/

/beta
```

Sometimes the mobile API exposes functionality not present in the browser.

# Chapter 13 — Status Codes

Status codes reveal information.

Example:

```text
200

Endpoint exists
```

```text
401

Exists

Authentication required
```

```text
403

Exists

Access denied
```

```text
404

May not exist
```

Different responses help map the API.

---

# Chapter 14 — Content Discovery

Many endpoints are never linked from the UI.

Examples:

```text
/admin

/debug

/export

/backup

/internal

/reports

/graphql
```

Content discovery tools can help identify hidden paths within the authorized scope of an engagement.

# Chapter 15 — Parameter Discovery

Endpoints are only part of the picture.

Example:

```http
GET /search
```

Possible parameters:

```text
q=

sort=

limit=

offset=

page=

admin=

debug=
```

Hidden parameters sometimes enable undocumented behavior.

---

# Chapter 16 — Header Discovery

Headers matter too.

Look for:

```text
Authorization

API-Key

X-API-Key

X-Tenant-ID

X-Forwarded-For

Origin

Referer
```

Some APIs behave differently depending on request headers.

# Chapter 17 — Authentication Mapping

Determine:

- Where does login occur?
    
- JWT?
    
- OAuth?
    
- API key?
    
- Cookie?
    
- Session ID?
    

Example:

```text
Login

↓

JWT

↓

Authorization: Bearer ...
```

Understanding authentication is essential before testing authorization.

---

# Chapter 18 — Technology Fingerprinting

Identify technologies such as:

- Web server
    
- Framework
    
- CDN
    
- WAF
    
- Reverse proxy
    
- Cloud provider
    

Useful clues include:

- Response headers
    
- Cookies
    
- Error messages
    
- TLS characteristics
    

This helps you understand how the application is built.

---

# Chapter 19 — Building the Endpoint Inventory

Professionals maintain an inventory like this:

|Method|Endpoint|Auth|Notes|
|---|---|---|---|
|POST|`/api/login`|No|JWT issued|
|GET|`/api/profile`|Yes|Current user|
|GET|`/api/users/{id}`|Yes|User object|
|POST|`/api/orders`|Yes|Creates order|
|DELETE|`/api/orders/{id}`|Yes|Deletes order|

This inventory becomes the foundation for all later testing.

# Real-World Recon Workflow

Suppose you're authorized to assess:

```text
api.company.com
```

A disciplined workflow might look like:

### Step 1

Fingerprint the application.

Identify:

- Server
    
- CDN
    
- WAF
    
- Framework
    

---

### Step 2

Browse normally.

Capture all traffic.

---

### Step 3

Inspect JavaScript.

Extract API endpoints.

---

### Step 4

Check for:

```text
/swagger

/openapi.json

/graphql

/health

/metrics
```

---

### Step 5

Identify authentication.

- JWT?
    
- OAuth?
    
- API keys?
    
- Cookies?
    

---

### Step 6

Map every endpoint.

Include:

- Method
    
- Parameters
    
- Authentication
    
- Role
    
- Notes
    

---

### Step 7

Only now begin testing:

- BOLA
    
- BFLA
    
- BOPLA
    
- SSRF
    
- Authentication
    
- Resource consumption
    
- Business logic
